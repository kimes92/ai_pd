## 목표

교정 노트에서 **활성 타이핑 박스가 항상 화면에 보이도록** 만들고, 사용자가 계속 입력해도 교정 대상이 누락되지 않게 안정화합니다.

## 확인된 원인

현재 활성 박스는 코드상 렌더링되어 있지만, `overflow-y-auto` 내부의 맨 아래 요소이면서 `sticky bottom-32`로 배치되어 있습니다. 그래서 다음 상황에서 실제 화면에서는 안 보이거나 하단 도구바에 가려질 수 있습니다.

- 교정 스트림 영역이 길어져 내부 스크롤 하단으로 내려가야만 박스가 보이는 구조
- 하단 고정 툴바와 sticky offset이 겹치는 구조
- 빈 노트/기존 노트/유튜브-오디오 좌측 패널 여부에 따라 editor 높이가 달라지는 구조
- 사용자가 상단 교정 textarea에 입력하면 활성 박스 파이프라인을 타지 않아 교정이 누락되는 구조

## 수정 계획

### 1. 활성 박스를 스크롤 컨테이너 밖으로 분리

현재 구조:

```text
[스크롤 영역]
  교정 textarea
  실패 배너
  spacer
  sticky 활성 박스
```

수정 구조:

```text
[교정 스트림 스크롤 영역]
  교정 textarea
  실패 배너

[항상 보이는 활성 박스 영역]
  작성 중 라벨
  활성 textarea
```

이렇게 바꾸면 활성 박스가 스크롤 맨 아래에 묻히지 않고 항상 화면 하단 쪽에 고정적으로 보입니다.

### 2. 하단 툴바와 겹치지 않도록 안전 여백 적용

활성 박스 컨테이너에 다음 기준을 적용합니다.

- 하단 툴바 위로 충분히 띄움
- 모바일/태블릿/데스크톱 모두 동일하게 `15vh`에 가까운 여유 유지
- editor 전체에 `pb` 여백을 과하게 넣는 방식이 아니라, 활성 박스 자체의 영역을 명확히 확보

### 3. 활성 박스 시각 강조

사용자가 어디에 입력해야 하는지 바로 알 수 있도록:

- `border-primary` 계열 테두리 유지
- 배경을 더 뚜렷하게 조정
- 라벨을 `작성 중`으로 고정 표시
- 빈 상태에서도 최소 높이를 보장
- placeholder가 흐릿해서 안 보이는 문제 방지

### 4. 교정 누락 방지

입력 경로를 명확히 분리합니다.

- 상단 교정 영역: 이미 교정된 내용 수정 전용
- 하단 활성 박스: 새로 이어 쓰는 입력 전용

그리고 다음 동작을 보장합니다.

- Enter 입력 시 길이와 무관하게 즉시 flush
- 200자 이상에서 1초 정지 시 flush
- 200자 이상에서 `. , ? ! 。` 입력 시 flush
- flush 직후 활성 박스는 비워지고 focus 유지
- 실패 시 원문 삽입 + 재교정 버튼 유지

### 5. 실제 화면 확인

수정 후 브라우저에서 `/ai-note`를 열어 다음을 확인합니다.

- 빈 노트에서도 활성 박스가 바로 보이는지
- 기존 노트 내용이 길어도 활성 박스가 하단에 계속 보이는지
- 하단 툴바에 가려지지 않는지
- 활성 박스에 입력 후 Enter 시 상단으로 이동하는지
- 200자 이상 입력 후 정지/문장부호에서 교정이 작동하는지
